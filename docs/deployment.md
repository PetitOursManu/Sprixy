# Deployment

Sprixy is a single container (API + web UI + MCP endpoint) with a SQLite database and files on one volume.
No GPU is needed: all AI work runs at your providers; image processing runs on CPU.

## Docker Compose

```bash
cp .env.example .env
# set SPRIXY_MASTER_KEY=$(openssl rand -base64 32)
docker compose up -d --build
```

The app listens on port **3210**. Data lives in the `sprixy-data` volume (`/data` in the container):
`sprixy.db` (SQLite, WAL), `files/` (assets, sources, datasets, editor documents).

## Coolify (recommended)

The repository ships [`docker-compose.coolify.yml`](../docker-compose.coolify.yml), made for Coolify: no published
port (Coolify’s proxy serves your domain over HTTPS), a master key generated by Coolify, secure cookies, a persistent
`/data` volume and a health check.

1. **Projects → (your project) → + New → Public Repository** (or *Private Repository (GitHub App)* for a fork) and
   paste `https://github.com/PetitOursManu/Sprixy`, branch `main`.
2. **Build Pack: Docker Compose**, **Base Directory** `/`, **Docker Compose Location** `/docker-compose.coolify.yml`.
3. Coolify reads the file and lists the `sprixy` service. Set its **Domain** to your URL, e.g.
   `https://sprixy.example.com` (the port 3210 is already declared by `SERVICE_URL_SPRIXY_3210`; if your Coolify version
   asks for it, enter `https://sprixy.example.com:3210`). Point the DNS record of that domain to the VPS first.
4. **Deploy.** The first build takes a few minutes (dependencies, web build, ffmpeg).
5. Open the domain and **create your account immediately**: the first account becomes the admin, and sign-ups are then
   closed (`SPRIXY_ALLOW_SIGNUP=false`).
6. In **Environment Variables**, copy the generated `SERVICE_REALBASE64_MASTERKEY` value into your password manager.
   It encrypts your provider keys; if it is lost, keys must be re-entered.
7. In Sprixy, **Settings → Provider keys**: add your fal.ai (and/or OpenRouter) key.

Optional variables (Environment Variables tab): `SPRIXY_ALLOW_SIGNUP=true` to let other people sign up,
`SPRIXY_MAX_UPLOAD_MB`, `LOG_LEVEL`.

**Updates:** click **Redeploy** (or enable *Auto Deploy* on push). Data stays in the volume and migrations run at
boot. **Backups:** Persistent Storage shows the `sprixy-data` volume; back it up with Coolify’s scheduled backups or
`docker run --rm -v <volume>:/data -v $PWD:/b alpine tar czf /b/sprixy-data.tgz /data`.

**Moving an existing install:** copy the old `/data` volume into the new one *and* set
`SERVICE_REALBASE64_MASTERKEY` to the old `SPRIXY_MASTER_KEY` before the first start, otherwise stored provider keys
cannot be decrypted (re-entering them in Settings also works).

Using a Dockerfile resource instead also works: Build Pack *Dockerfile*, port `3210`, a volume mounted at `/data`, and
the variables `SPRIXY_MASTER_KEY` (`openssl rand -base64 32`) and `SPRIXY_SECURE_COOKIES=true` set by hand.

The first visitor creates the admin account — do it right after the first deployment.

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `SPRIXY_MASTER_KEY` | — | AES-256 key (base64/hex, 32 bytes) for provider keys. If unset, a key is generated in the data dir (dev only). |
| `SPRIXY_ALLOW_SIGNUP` | `false` | Allow sign-ups after the first admin account. |
| `SPRIXY_SECURE_COOKIES` | `false` | Mark the session cookie `Secure` (enable behind HTTPS). |
| `SPRIXY_DATA_DIR` | `/data` (image) / `./data` | Database and files. |
| `PORT` / `HOST` | `3210` / `0.0.0.0` | Listen address. |
| `SPRIXY_PUBLIC_URL` | — | Public URL (informational). |
| `FFMPEG_PATH` | `/usr/bin/ffmpeg` (image) | ffmpeg used to extract animation frames. |
| `SPRIXY_MAX_UPLOAD_MB` | `50` | Max upload size per file. |
| `SPRIXY_SESSION_DAYS` | `30` | Session lifetime. |
| `SPRIXY_POLL_INTERVAL_MS` | `1500` | fal queue polling interval. |
| `SPRIXY_JOB_TIMEOUT_MS` | `1800000` | Hard timeout per job. |
| `LOG_LEVEL` | `info` | Fastify/pino log level. |

## Reverse proxy

Any proxy works (Traefik in Coolify, Caddy, nginx). Allow request bodies of ~50 MB (uploads, editor saves) and keep
the default timeouts: long jobs are asynchronous and polled, no request stays open for long.

## Backups

Back up the `/data` volume (stop the container or use `sqlite3 sprixy.db ".backup backup.db"` for a hot copy) and keep
`SPRIXY_MASTER_KEY` alongside.

## Upgrades

Pull, rebuild, restart. Database migrations run automatically at boot. Interrupted fal jobs resume; other in-flight
jobs are marked as interrupted (nothing is billed twice by Sprixy).
