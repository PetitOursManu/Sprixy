Sprixy is a single container: the web app, the REST API, the MCP endpoint and this documentation (served at `/docs`).
It keeps a SQLite database and its files on one volume. No GPU is needed — AI work runs at your providers, image
processing runs on the CPU.

:::vars
domain = sprixy.example.com | Your domain
:::

:::tabs group=host
@tab Coolify
The repository ships [`docker-compose.coolify.yml`](https://github.com/PetitOursManu/Sprixy/blob/main/docker-compose.coolify.yml),
made for Coolify: no published port (Coolify's proxy serves your domain over HTTPS), a master key generated by
Coolify, secure cookies, a persistent `/data` volume and a health check.

:::steps id=coolify
1. **Add the repository.** In your Coolify project: **+ New → Public Repository** (or *Private Repository (GitHub App)*
   for a fork), paste `https://github.com/PetitOursManu/Sprixy`, branch `main`.
2. **Choose the compose file.** Build Pack **Docker Compose**, Base Directory `/`, Docker Compose Location
   `/docker-compose.coolify.yml`.
3. **Set the domain.** On the `sprixy` service, set the domain to `https://{{domain}}`. Port 3210 is already declared;
   if your Coolify version asks for it, enter `https://{{domain}}:3210`. Point the DNS record to the VPS first.
4. **Deploy.** The first build takes a few minutes (dependencies, web app, documentation, ffmpeg).
5. **Create your account right away.** Open `https://{{domain}}`: the first account becomes the admin, then sign-ups
   close.
6. **Save the master key.** In **Environment Variables**, copy `SERVICE_REALBASE64_MASTERKEY` into your password
   manager. It encrypts your provider keys.
7. **Add a provider key.** In Sprixy, **Settings → Provider keys**: paste your fal.ai and/or OpenRouter key.
:::

To give other people access, create their accounts under **Users** ([Users and allowances](users.md)).
Optional variables (Environment Variables tab): `SPRIXY_ALLOW_SIGNUP=true` to let anyone sign up instead,
`SPRIXY_MAX_UPLOAD_MB`, `LOG_LEVEL`.

**Updates:** click **Redeploy**, or turn on *Auto Deploy* to redeploy on every push. Data stays in the volume and
migrations run at boot.

@tab Docker Compose
:::steps id=compose
1. **Get the code.**
   ```bash
   git clone https://github.com/PetitOursManu/Sprixy.git && cd Sprixy
   cp .env.example .env
   ```
2. **Set a master key.** Generate one and paste it after `SPRIXY_MASTER_KEY=` in `.env`:
   ```bash
   openssl rand -base64 32
   ```
   Behind HTTPS, also set `SPRIXY_SECURE_COOKIES=true`.
3. **Start it.**
   ```bash
   docker compose up -d --build
   ```
4. **Check it answers.**
   ```bash
   curl http://localhost:3210/api/health
   ```
5. **Create your account** at `http://localhost:3210` (or `https://{{domain}}` behind your proxy). The first account
   becomes the admin.
:::

**Updates:** `git pull && docker compose up -d --build`. Migrations run at boot.
:::

:::warning Keep the master key
`SPRIXY_MASTER_KEY` (Coolify: `SERVICE_REALBASE64_MASTERKEY`) encrypts the provider keys stored in Sprixy. Without it,
they cannot be decrypted and must be entered again. Keep it in your password manager, next to your backups.
:::

## Moving an existing install

Copy the old `/data` volume into the new one **and** set the master key to the old value before the first start.
Otherwise the stored provider keys cannot be decrypted — entering them again in Settings also works.

:::why Why a Dockerfile resource also works
Coolify can build the `Dockerfile` directly: Build Pack *Dockerfile*, port `3210`, a volume mounted at `/data`, and the
variables `SPRIXY_MASTER_KEY` (`openssl rand -base64 32`) and `SPRIXY_SECURE_COOKIES=true` set by hand. The compose file
only saves you those steps.
:::

## Environment variables

| Variable | Default | Description |
| --- | --- | --- |
| `SPRIXY_MASTER_KEY` | — | AES-256 key (base64/hex, 32 bytes) for provider keys. If unset, a key is generated in the data dir (dev only). |
| `SPRIXY_ALLOW_SIGNUP` | `false` | Allow sign-ups after the first admin account. |
| `SPRIXY_SECURE_COOKIES` | `false` | Mark the session cookie `Secure` (enable behind HTTPS). |
| `SPRIXY_DATA_DIR` | `/data` (image) / `./data` | Database and files. |
| `PORT` / `HOST` | `3210` / `0.0.0.0` | Listen address. |
| `SPRIXY_PUBLIC_URL` | — | Public URL (informational). |
| `FFMPEG_PATH` | `/usr/bin/ffmpeg` (image) | ffmpeg used to extract animation frames. |
| `SPRIXY_MAX_UPLOAD_MB` | `50` | Max upload size per file. |
| `SPRIXY_SESSION_DAYS` | `30` | Session lifetime. |
| `SPRIXY_POLL_INTERVAL_MS` | `1500` | fal queue polling interval. |
| `SPRIXY_JOB_TIMEOUT_MS` | `1800000` | Hard timeout per job. |
| `LOG_LEVEL` | `info` | Fastify/pino log level. |

## Reverse proxy

Any proxy works (Traefik in Coolify, Caddy, nginx). Allow request bodies of about 50 MB (uploads, editor saves) and
keep the default timeouts: long jobs are asynchronous and polled, so no request stays open for long.

## Backups

Back up the `/data` volume — stop the container, or take a hot copy with `sqlite3 sprixy.db ".backup backup.db"` —
and keep the master key alongside. In Coolify, the volume appears under **Persistent Storage**; you can also run:

```bash
docker run --rm -v <volume>:/data -v $PWD:/b alpine tar czf /b/sprixy-data.tgz /data
```

## Upgrades

Pull, rebuild, restart. Database migrations run automatically at boot. Interrupted fal.ai jobs resume; other
in-flight jobs are marked as interrupted, and nothing is billed twice by Sprixy.
